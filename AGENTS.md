# Task Earn Hub - Reward System Economics & Platform Instructions

## Overview
This document outlines the core mathematical and economic model for the "Task Earn Hub" platform. It must be strictly adhered to when building backend logic, database schemas, and user interfaces related to earnings, referrals, and plan purchases.

## Core Loop
1. **Buy a Plan** -> User pays the `Plan Price` to start earning.
2. **Earn Daily Reward** -> User receives a fixed `Daily Reward` for 30 days.
3. **Invite Members** -> User must invite a `Members Required` count to maximize earnings and qualify for total withdrawals.
4. **Get Referral Bonus** -> User receives a flat `50 PKR` per invited member.
5. **Receive Total Reward** -> The user's final earning is the sum of their 30-day daily rewards and their total referral bonuses.

## Economics & Formulas
The system is strategically designed to be profitable for the platform. It ensures that user withdrawals (`User Total Reward`) are always less than the total revenue generated by the user's initial purchase and the required purchases from their referrals.

**Variables & Formulas:**
* `P` = Plan Price (PKR)
* `D` = Daily Reward (PKR)
* `M` = Members Required (Count)
* `R30` = 30-Day Reward = `D * 30`
* `M_rev` = Members Revenue = `M * 250` *(Assumes each referred member brings at least a base 250 PKR purchase to the platform)*
* `Rev_A` = Platform Revenue = `P + M_rev`
* `RefBonus` = Referral Bonus = `M * 50`
* `Total_B` = User Total Reward = `R30 + RefBonus`
* `Profit` = Platform Profit = `Rev_A - Total_B`

## Developer Architecture Guidelines
1. **Strict Calculations:** Whenever building backend endpoints for balance calculation, referral crediting, or withdrawal validation, use these exact formulas. Do not invent arbitrary percentages.
2. **Referral Gating:** Withdrawals or total reward unlocks must be validated against the `Members Required` count for the user's specific active plan.
3. **Data Source of Truth:** Do not alter these numbers without explicit admin request. Ensure the frontend data representations (`src/data.ts`) match this matrix exactly.
4. **Persistent Knowledge:** This document ensures that the AI assistant maintains deep, persistent context of the business model and profit margins across all future chat sessions and system builds.

## Database Architecture (Supabase)
The system uses Supabase with the following referral and auth architecture:
1. **Authentication**: Handled via Supabase Auth (Email/Password). Username and Phone number are collected during signup and stored in the `profiles` table. Email confirmation is disabled.
2. **Profile Creation**: A PostgreSQL trigger automatically creates a row in the `public.profiles` table whenever a new user registers.
3. **Referral Code Generation**: During the profile creation trigger, a unique 6-character alphanumeric referral code is automatically generated for every user.
4. **Referral Tracking**: When a user signs up using a referral link (`?ref=CODE`), the `referred_by` column in their profile is populated with that code. This allows the system to query how many members a specific user has invited and calculate their total referral bonuses.

## Profit & Business Logic
The core business model revolves around a sustainable profit margin for the platform administrator:
- **User Perspective**: A user buys a plan, earns a daily fixed reward, and is incentivized to invite members. For each member invited, they get a flat 50 PKR bonus (or the custom `referral_bonus` configured by Admin). To withdraw their maximum potential, they must hit the required member count.
- **Platform/Admin Perspective**: Every required member invited by a user is expected to bring in at least a base plan purchase (e.g., 250 PKR, configurable via `base_member_plan_price`). The platform's total revenue (Plan Price + Revenue from required members) is always significantly higher than the total payout to the user (duration reward + referral bonuses), guaranteeing a positive Platform Profit (as shown in the matrix above).

## Admin Full Customization & Smart Economic Validation Engine
1. **Full Plans CRUD (`src/lib/economics.ts` & `src/views/AdminView.tsx`)**:
   - Admins can create new plans (Plan #11+), edit existing plans, toggle visibility (`is_active`), delete custom plans, or restore the official 10-plan matrix.
   - Customizable fields per plan: `name`, `plan_price` (`P`), `daily_reward` (`D`), `total_days` (`Days`, default 30), `members_required` (`M`), `thirty_day_reward` (`R30`), `user_total_reward` (`Total_B`), `icon`, `theme_key`, and `is_active`.
   - Dual-Persistence: Extended plan metadata is persisted both in `public.plans` columns and mirrored in `public.app_settings` (`plans_meta_json`) so customization works seamlessly across any database state.
2. **Live Formula & Profit Diagnostics with Auto-Fix**:
   - Auto-calculates `R_days = D * Days`, `RefBonus = M * referral_bonus`, `Total_B = R_days + RefBonus`, `M_rev = M * base_member_plan_price`, `Rev_A = P + M_rev`, and `Profit = Rev_A - Total_B`.
   - Manual override mode allows custom `thirty_day_reward` and `user_total_reward` values while displaying bilingual (English + Roman Urdu) diagnostic reasons if formulas mismatch, along with one-click **Auto-Fix** remedies.
   - **Strict Loss Protection**: Saving a plan is blocked if `Profit <= 0` (`Total_B >= Rev_A`), showing the exact PKR deficit and one-click remedies (Reduce Daily Reward or Increase Required Members).
3. **Team Salary, Invite & Withdrawal Customization (`public.app_settings`)**:
   - **Team Salary Levels 1–6 (`src/lib/rewardLevels.ts`)**: Configurable member goals (`level_1_req`..`level_6_req`) and custom PKR reward payouts (`level_1_reward`..`level_6_reward`, where `0` auto-calculates `req * referral_bonus`), complete with a live per-level economic margin audit.
   - **Global Economic & Invite Rules**: Configurable `referral_bonus`, `base_member_plan_price`, `free_reward_days` (0–30 days unlocked without referrals, with Day 1 unlocked immediately at 0h upon activation), `min_withdraw_amount`, and `invite_share_message` template (`{username}`, `{link}`, `{code}`).
